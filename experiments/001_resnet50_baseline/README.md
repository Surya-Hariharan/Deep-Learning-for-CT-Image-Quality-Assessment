# Experiment 001: ResNet50 baseline

**Status: training completed (2026-09-13). Test-set evaluation NOT yet performed.**

## Objective

An **Ohashi-style RadImageNet ResNet50 CT-IQA model adapted to LDCT-IQAC**
(see `docs/replication/replication_scope.md`). This is **not** an exact
reproduction of the original paper's experiment -- the paper used
synthetic Gaussian noise/blur degradation and VIF labels on its own
dataset; this experiment uses real LDCT-IQAC CT images with real
radiologist-assigned quality scores instead (see
`docs/replication/dataset_adaptation.md`, `docs/replication/deviations.md`).
Only the model architecture and the paper's training configuration
(Adam/MSE/batch 64/30 epochs/lr 1e-3) are replicated.

Orchestrated by `notebooks/03_training/01_resnet50_baseline.ipynb`
(generated by `tools/build_training_notebook.py`).

## Dataset

LDCT-IQAC (see `docs/replication/dataset_adaptation.md`): 1000 training
images, split into 900 training / 100 validation (seeded 90/10 split of
the training set only); 300 held-out test images, **untouched by this
experiment** -- no test-set data, metric, or decision influenced training,
checkpoint selection, or any hyperparameter here.

## Model

`OhashiResNet50` (`src/ct_iqa/models/`): RadImageNet-pretrained ResNet50
backbone (Keras/RadImageNet stride convention) -> Global Average Pooling ->
Dropout(0.5) -> Linear(2048 -> 1) -> Sigmoid. No architectural additions.

**RadImageNet initialization: verified.**
`weights/pretrained/radimagenet/resnet50/radimagenet_resnet50_backbone.pt`
loaded with **265/318 backbone keys matched, 0 unexpected keys**; the
remaining 53 "missing" keys are all non-learned `num_batches_tracked`
counters (expected). No ImageNet fallback occurred anywhere in this run.

## Preprocessing / target

`LDCT-IQAC image [0,1] -> center crop 224x224 -> [-1,1] normalization ->
grayscale replicated to 3 channels (inside the model, not the DataLoader)
-> ResNet50`. Target: raw score `[0, 4] -> normalize_score -> [0, 1]`
(Sigmoid-compatible). See `docs/replication/deviations.md` for why each of
these is a paper fact vs. an implementation decision.

## Training configuration

| | |
|---|---|
| optimizer | Adam |
| loss | MSE (normalized `[0,1]` target space) |
| batch size | 64 |
| learning rate | 1e-3 |
| epochs | 30 (completed, no early stopping) |
| dropout | 0.5 |
| seed | 42 |

## Environment

Python 3.10.20, PyTorch 2.5.1+cu121, CUDA available, GPU: NVIDIA GeForce
RTX 4060 Laptop GPU, device=`cuda`. Deterministic cuDNN requested
(`torch.backends.cudnn.deterministic=True`, `benchmark=False` via
`ct_iqa.utils.seed.set_seed`) -- see
`docs/replication/reproducibility.md` for the resulting
determinism/throughput tradeoff on this GPU run.

## Actual measured results (training run)

**These are real, measured numbers from this run -- not fabricated, not
paper numbers, not test-set numbers.**

- Epochs completed: **30/30**, no NaN/Inf loss at any epoch (verified
  programmatically over the full history).
- Best epoch (0-indexed): **21** (i.e. the 22nd epoch), selected purely by
  lowest **validation**-split loss, per the training loop's existing
  best-checkpoint logic -- the test set played no role.
- Best validation loss (normalized MSE): **0.003052**
- Final (epoch 30) training loss: **0.003255**
- Final (epoch 30) validation loss: **0.018703**
- Validation-split correlation metrics, computed post-hoc on the
  end-of-training model (raw `[0,4]` score scale, via
  `ct_iqa.evaluation.metrics.compute_metrics`; **validation split only,
  NOT the test set**): MSE **0.299**, PLCC **0.948**, SROCC **0.949**,
  KROCC **0.820**.
- The validation loss curve is visibly noisier than the training loss
  curve (e.g. spikes to ~0.108 at epochs 3 and 29) -- expected given the
  validation split is only 100 images (2 batches at batch size 64); this
  is reported as an observed characteristic of the run, not treated as a
  bug or "fixed" by changing the split policy or architecture.
- Full per-epoch history: `history.json` in this directory. Loss curve
  figure: `results/figures/001_resnet50_baseline_training_curve.png`.

## Checkpoint

`checkpoint/best.pt` (gitignored, see root `.gitignore`) contains:
`model_state_dict`, `optimizer_state_dict`, `epoch` (21), `val_loss`
(0.003052), the resolved `config`, and `seed` (42) -- not just bare
weights. **Independently reloaded in a fresh model instance/process** (not
the in-memory training object) and verified to produce finite, `[0,1]`-bounded
predictions on a real validation batch.

## Unexpected events

None. No NaN/Inf loss, no collapsed predictions, gradients present and
parameters updating throughout (verified via the pre-training smoke test);
the noisy validation curve (above) is the only notable characteristic, and
is a property of the small validation split size, not an implementation
fault.

## What this experiment does NOT show

**Test-set performance was not evaluated in this experiment and must not
be inferred from the validation numbers above.** The next step is an
independent evaluation of `checkpoint/best.pt` against the untouched
300-image LDCT-IQAC test set, in
`notebooks/04_evaluation/01_test_set_evaluation.ipynb`. This experiment
also does not reproduce the original Ohashi paper's numerical results --
different dataset, different label semantics (see
`docs/replication/dataset_adaptation.md`) -- and no such claim is made
here.
