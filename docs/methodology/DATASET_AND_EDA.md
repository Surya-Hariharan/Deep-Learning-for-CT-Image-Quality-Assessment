# Dataset audit and EDA

Generated by `tools/run_eda.py` (read-only; outputs in `reports/eda/`, summary `reports/eda/dataset_audit.json`). No data file is modified.
Dataset: the LDCT-IQAC data already configured in the repository (1000 labeled training-set images, 300 official test images).

## Integrity (all checks passed)
- 1000 train images and 1000 labels (no missing, no extra); 300 test images and 300 labels. All 1300 TIFFs decode; mode `F` (float32),
  512x512, pixel range [0, 1], all finite. Labels numeric and within [0, 4].
- Frozen split manifest verified, not regenerated: 800 train / 100 validation / 100 calibration, seed 2026, no pairwise overlap;
  recomputed canonical hash `be5831c5...0a16` equals the embedded hash and the expected prefix/suffix. (Raw file SHA-256 differs from the canonical
  hash by design.) The test set is not in the manifest.
- Exact duplicates (SHA-256 of file bytes): none, within or across partitions.

## Finding that limits every validation-based conclusion: same-anatomy groups cross the image-level split
(Follow-up audit with group-size structure and identifier search: [SPLIT_AND_CALIBRATION_AUDIT](../audit/SPLIT_AND_CALIBRATION_AUDIT.md). The groups come from image similarity, not from identifiers; patient-level independence is unknown in both directions.)
Thumbnail-correlation screening (64x64 Pearson r; `reports/eda/dataset_audit.json`, `anatomy_groups_thr0.999.csv`) shows the labeled images are
repeated renderings of the same slices at different quality levels (full-resolution correlation about 0.9996-0.9998 between members; labels differ):
- At r > 0.999 the 1300 images form 124 groups with no singletons (largest groups 40, 20, 20, 20, 10, ...); at r > 0.99, 83 groups.
- **100% of validation images and 100% of calibration images have at least one same-anatomy group member in the training partition.**
- **0% of official-test images** have a same-anatomy partner among the labeled training images (the test set is anatomy-disjoint).
- dHash(8x8) was also computed but is uninformative for CT slices (many collisions between different slices).

Consequences (carried into every experiment document):
1. The split is image-level, not anatomy-/patient-level; validation and calibration metrics measure interpolation between quality levels of *seen anatomy*
   and are optimistic. This probably explains the large validation-to-test gap of the historical runs (validation PLCC about 0.96-0.98 vs test PLCC 0.85-0.87).
2. The official test set is the only anatomy-disjoint evaluation available, but it was already examined by historical 001 and 003, so it is
   retrospective, not confirmatory.
3. Bootstrap intervals over images treat dependent images as independent and are too narrow. Conformal exchangeability between calibration and
   validation images is plausible (both share anatomy with train); it is **not** expected to hold for the anatomy-disjoint test set.
4. The frozen split is not altered (project rule). Group-aware analysis, if added, is a clearly labeled supplementary analysis.

## Image properties
All images 512x512 float32 in [0, 1]; mean pixel about 0.366-0.370 for train/validation/calibration and 0.411 for test (different anatomy mix);
per-image mean/std table in `reports/eda/image_properties.csv`. Figures: `score_distributions.png`, `pixel_statistics.png`, `representative_images.png`.
Preprocessing (224 center crop of 512x512, `2x-1`) does not change label semantics: it is a pixel-space operation applied identically to every image;
note that cropping discards the outer ~64% of the image area, which could remove noise/artifact cues outside the crop (not evaluated).

## Reproduce
`conda run -n torch-gpu python tools/run_eda.py` (about a minute). Dataset manifest hash and label-file SHA-256 values are in the JSON report.
