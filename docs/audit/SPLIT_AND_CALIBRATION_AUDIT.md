# Split-grouping and Experiment C calibration audit

Generated by `tools/audit_split_and_calibration.py` (output `reports/audit/split_and_calibration_audit.json`). Read-only; no training, no new test-set decisions. Written after the study-v2 results (commit `c10014f`), which are preserved unchanged as the historical baseline of this study.

## 1. What grouping information exists
- **Identifiers: none.** TIFF headers hold only generic `tifffile` shape/resolution tags; file names are shuffled indices (`0000.tif`...); labels are one averaged score per image. There is no patient, scan, or slice identifier anywhere in the repository.
- **Recovered structure (image similarity, not identity).** Connected components of 64x64-thumbnail Pearson r > 0.999 give 124 groups over the 1300 images: **120 groups of exactly 10 images**, 3 of 20 and 1 of 40. Within a group the full-resolution correlation is about 0.9996-0.9998 while labels differ (on average 8.7 distinct label values per group). This pattern fits *one source slice rendered at 10 quality levels*: about 100 sources in the 1000 labeled images and 30 sources in the 300 test images. The larger groups are plausibly neighbouring/similar slices that merged.
- **Across partitions:** 82 of the 94 labeled groups span more than one of train/validation/calibration; every validation and calibration image has at least one group mate in train. **None of the 30 test groups shares a group with any labeled image.**
- **What this does not show:** whether different sources come from the same patient, or even that the groups are literally one slice; the evidence is image similarity. Likewise the validation-vs-test performance gap (PLCC 0.98 vs 0.87) is *consistent with* this structure but does not by itself prove leakage; test images also differ in score granularity (six raters) and anatomy mix (mean pixel 0.41 vs 0.37).

## 2. Experiment C calibration - independent verification
Plain-numpy re-implementation from the saved prediction CSVs (not using `ct_iqa.evaluation`):
- Formula: sigma = 4·exp(s/2), mu = 4·sigmoid output; r_i = |y_i - mu_i| / sigma_i on the 100 calibration images; k = ceil(101·0.9) = 91; q = 91st smallest r; interval mu ± q·sigma; coverage = fraction of labels inside.
- **All checks pass** for all three final seeds: recomputed q and coverages equal the stored `calibration.json` / `metrics_test.json` values (differences below 1e-6, CSV rounding); the calibration predictions are exactly the 100 manifest calibration files and are disjoint from the 100 validation files; mu equals 4x the normalized output.
- Formula sanity check on synthetic exchangeable data: coverage 0.8965 over 2000 trials (Monte Carlo SE about 0.007, consistent with the guaranteed >= 0.90).
- Intervals were evaluated on samples not used to fit q (validation, test). Target coverage 0.90 in code, config and docs agree.

Covered counts (learned-sigma intervals; unclipped = clipped here):

| Seed | q | Validation covered | Test covered | Test coverage |
|---|---|---|---|---|
| 1 | 2.145 | 96 / 100 | 198 / 300 | 0.660 |
| 2 | 1.723 | 92 / 100 | 188 / 300 | 0.627 |
| 3 | 2.162 | 95 / 100 | 186 / 300 | 0.620 |

Per-seed coverage is computed first and then averaged (0.636). The three seeds score the **same** 300 test images, so the pooled 572/900 is not 900 independent observations; the effective sample for the test coverage is 300 images (binomial SE about 0.03) and, because of image grouping, fewer independent units still (30 sources).

## 3. Why test coverage is far below 0.90 (diagnostic, not a fix)
Conformal coverage requires calibration and evaluation points to be exchangeable. They are not:

| Seed | Median normalized residual cal / val / test | RMSE cal / val / test | q used | q that would give 90% on test (diagnostic only) |
|---|---|---|---|---|
| 1 | 0.62 / 0.86 / 1.54 | 0.27 / 0.27 / 0.55 | 2.14 | 3.58 |
| 2 | 0.67 / 0.58 / 1.37 | 0.30 / 0.26 / 0.60 | 1.72 | 3.23 |
| 3 | 0.72 / 0.70 / 1.73 | 0.29 / 0.26 / 0.63 | 2.16 | 3.61 |

Calibration images behave like validation images (their sources are in the training set), so the calibration quantile is calibrated to an easy distribution; test residuals are 2-2.5x larger relative to sigma. A quantile large enough for the test set (3.2-3.6) would be about 1.5-2x the one fitted. The q column on the right was looked at only for this explanation and is **not** used anywhere. The same mechanism explains the constant-width comparator's 0.54 test coverage. Conclusion: the implementation is correct; the *protocol* (calibrating on images whose sources were seen in training) is what fails to transfer.

## 4. Consequences and decision
1. Report current intervals as **exploratory**: the image-level bootstrap treats the 10 variants of a source as independent, so its intervals are too narrow. The statements "B worse" and "C worse on validation" are descriptive point estimates with overconfident intervals, not significance claims.
2. Calibration claims for C are limited to: *conformal intervals on in-distribution (shared-source) data reach nominal coverage; they do not on unseen sources.*
3. **Group-aware evaluation is feasible without identifiers**: use the recovered groups (about 100 source groups in the labeled set) for a grouped train/validation/calibration split, group-level bootstrap resampling (resample sources, not images), and group-aware cross-fitting of conformal calibration. This would be a **new, separately labelled protocol (study v3)**, defined before running, with its own freeze; it does not replace the v2 split or its results. Because the official test set has already been examined, results on it can never become a confirmatory test, and a new protocol should reserve the existing test sources only for a final, once-only exploratory report (or use grouped cross-validation on the labeled set as the primary evidence).
4. Not done in this audit: no grouped re-split, retraining or group-bootstrap has been run; those require a protocol decision from the project owner.
